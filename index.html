关于 Finx

About Finx

Finx 是 Fink 的延续。Fink 是 macOS 上老牌的包管理器，建立在 Debian 的 dpkg / apt 体系之上：它下载原始源码，按需打补丁，为 Darwin 配置好，编译并安装。

Finx is the continuation of Fink, the long-standing macOS package manager built on Debian's dpkg / apt stack: it downloads original source releases, patches them when necessary, configures them for Darwin, then compiles and installs.

名字里的 x 取「扩展」之意。dpkg / apt 的依赖求解与副作用控制至今依然先进，值得保留；需要扩展的是安装前缀、文档与可维护性 —— 而不是换掉内核。

The x stands for extension. dpkg / apt dependency solving and side-effect control are still ahead of their time and worth keeping; what needs extending is the install prefix, the documentation, and maintainability — not the kernel.

为什么选择 Finx

Why Finx

  • 真有依赖求解。 走 dpkg / apt，而不是「先装这个再装那个」的脚本约定：Depends、Conflicts、Provides、虚拟包、shlibs 符号依赖都由包管理器算。
  • 副作用可控。 conffiles 让你改过的配置在升级时不被覆盖；preinst / postinst / prerm / postrm 四个维护者脚本定义了每一步该做什么。
  • 落地前先求解。 安装前会用一致性求解算出「为了装这批包，需要临时卸掉谁」，而不是装到一半才发现冲突。
  • 单一规范前缀。 全仓库统一到 /opt/finx，不再按 macOS 版本在 /sw 与 /opt/sw 之间分叉。
  • 源码与二进制双分发。 有预编译包就下，没有就从源码编；两者走同一条安装路径。
  • 纯 Perl + Shell。 没有编译型依赖，读代码不需要先配好工具链。
  • 锁是真锁。 先抢 dpkg 数据库锁再 exec，锁随子进程继承，并发操作不会互相踩。
  • Real dependency solving. dpkg / apt, not a "install this before that" convention: Depends, Conflicts, Provides, virtual packages and shlibs symbol dependencies are computed by the package manager.
  • Controlled side effects. conffiles keep your edited configuration across upgrades; the four maintainer scripts — preinst, postinst, prerm, postrm — define exactly what happens at each step.
  • Resolved before landing. A consistency pass works out which packages must be temporarily removed to satisfy the install, instead of discovering the conflict halfway through.
  • One canonical prefix. Everything is unified on /opt/finx; no more splitting between /sw and /opt/sw by macOS version.
  • Source and binary distribution. Use a prebuilt package when one exists, compile when it does not; both take the same install path.
  • Perl and Shell only. No compiled dependencies, so reading the code does not require a working toolchain.
  • Real locking. The dpkg database lock is taken before exec, so the child inherits it and concurrent operations cannot trample each other.

安装 Finx

Install Finx

当前阶段不推荐安装（开发者除外）。 一条命令已经可用，但预编译种子还没发布， 所以它会退回到源码编译 —— 需要 Xcode Command Line Tools，首次要十几分钟。
Not recommended for installation yet, developers excepted. The one-liner works, but no prebuilt seed has been published, so it falls back to a source build — that needs the Xcode Command Line Tools and takes a while the first time.

一条命令

One command

$ /bin/bash -c "$(curl -fsSL https://sh.finx.sh/finx.sh)"

脚本从 jsDelivr 取，国内可直连；仓库里同一份文件也在 finx-install/install.sh，它就是可以直接下载的那一个。 参数放在 -- 之后 —— 装到别处、或者强制走源码：

The script is served by jsDelivr for reachability; the same file lives at finx-install/install.sh in the repository -- it is the one file you can download. Options go after -- — install elsewhere, or force a source build: 

$ … -- --prefix=/opt/finx
$ … -- --from-source
$ … -- --no-path

它怎么决定装法

How it picks a method

情况 Situation 走哪条路 Method
默认 Default 先探种子，探不到就源码自举并说明原因 Probe for a seed; fall back to source and say why
--from-source --from-source 直接源码自举 Build from source directly
--no-fallback --no-fallback 探不到种子就失败，不换源 Fail when no seed is reachable
--seed-dir / --manifest-url --seed-dir / --manifest-url 严格用指定的来源 Use the given source, strictly

源码模式需要什么

What the source path needs

Finx 的起点是宿主的 C 编译器：先把 tar 与 dpkg 编到临时脚手架， 再用它们把基础包装进 /opt/finx，最后删掉脚手架。安装器会先查 cc、pod2man、perl，缺一个就当场停下，不会等到半小时后才失败。

Finx starts from the host C compiler: it builds tar and dpkg into a scratch tree, uses them to install the base packages into /opt/finx, then removes the scaffolding. The installer checks for cc, pod2man and perl up front, so a missing one fails immediately instead of half an hour later. 

$ xcode-select --install
$ sudo xcodebuild -license

配置 shell 环境

Set up your shell

$ . /opt/finx/bin/init.sh

想长期生效，让 /opt/finx/bin/pathsetup.sh 改你的 shell 启动文件。装包操作需要 root， finx 会自己调用 sudo。

To make it permanent, let /opt/finx/bin/pathsetup.sh edit your shell startup file. Package operations need root; finx invokes sudo itself.

使用

Usage

$ finx install wget          # 安装
$ finx list                  # 列出可用软件包
$ finx describe wget        # 查看包描述
$ finx remove wget           # 卸载，保留配置文件
$ finx purge wget            # 卸载并删除配置文件
$ finx selfupdate            # 更新包管理器自身
$ finx update-all            # 更新全部已安装包

装包操作需要 root，finx 会自己调用 sudo，不必手动加。

Package operations need root; finx invokes sudo itself, so you do not add it by hand.
